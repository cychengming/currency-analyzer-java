# 2021 → 2026 技术栈差异（JDK 21 / 25 / 27 全覆盖）

> 用途：简历上还写着 `springBootVersion = '2.3.4.RELEASE'` / `springCloudVersion = 'Hoxton.SR8'` 的话，面试官一定会问「这几年你用过什么新的」。这篇给你能对上号的答案。
> 所有 JDK 特性都来自 openjdk.org 的官方 JEP 列表，版本号来自官方系统要求页。
> 关联：[[后端研发题库]] ｜ 来源核验见 [[核验表-2026-10-28]]

---

## 一、速览：你的栈 vs 现在的栈

| 维度 | 你简历上的（2021） | 2026 现状 |
|---|---|---|
| JDK | 8 | **21（LTS，2023-09-19）** 和 **25（LTS，2025-09-16）** 是当前两个 LTS；**27 已于 2026-09-15 发布，非 LTS** |
| Spring Boot | 2.3.4.RELEASE | **4.1.2**（要求 Java 17+，兼容到 **Java 27**，需 Spring Framework **7.0.10+**） |
| Spring Cloud | Hoxton.SR8（Netflix 组件为主） | Netflix 一批模块已被移除（Ribbon/Hystrix/Zuul 那代），注册配置中心主流是 **Nacos** |
| 命名空间 | `javax.*` | `jakarta.*`（Boot 3.0 起；对应 Servlet 6.1 / Tomcat 11） |
| 内置容器 | Tomcat 9 / Servlet 4 | **Tomcat 11.0.x / Servlet 6.1**（Boot 4.1 要求） |
| 构建 | Maven 3.x / Gradle 6 | Maven 3.6.3+ / **Gradle 8.14+ 或 9.x** |
| 原生镜像 | 无 | GraalVM **25** 及以上 |
| GC | CMS / G1 | **G1 默认**；有 Generational ZGC（21）与 Generational Shenandoah（25）；**27 把 G1 默认化推到所有环境** |
| 并发 | 线程池 + Future | **虚拟线程（21 正式）**；Structured Concurrency 到 27 仍是预览（第七轮） |

**一句话结论**：你不是「落后几年」，是**跨了两个大版本基线**（Java 8→21/25、Boot 2→4、javax→jakarta）。面试时坦率承认 + 说清迁移影响，比硬编「用过」强得多。

### 特性演化追踪表（21 → 27，全部来自官方 JEP 列表）

| 特性 | 21 | 22 | 23 | 24 | 25 | 27 |
|---|---|---|---|---|---|---|
| String Templates | 430 预览 | **459 第二轮预览** | — | — | — | — |
| Virtual Threads | **444 正式** | — | — | 491 修 pinning | — | — |
| Structured Concurrency | 453 预览 | 462 二轮 | 480 三轮 | 499 四轮 | 505 五轮 | 533 七轮 |
| Scoped Values | 446 预览 | 464 二轮 | 481 三轮 | 487 四轮 | **506 正式** | — |
| Compact Object Headers | — | — | — | 450 实验 | **519 正式** | 534 默认 |
| ZGC 分代 | 439 正式（可选） | — | **474 默认分代** | 490 删除非分代 | — | — |
| Class-File API | — | 457 预览 | 466 二轮 | **484 正式** | — | — |
| Stream Gatherers | — | 461 预览 | 473 二轮 | **485 正式** | — | — |
| 灵活构造器体 | — | 447 预览 | 482 二轮 | 492 三轮 | **513 正式** | — |
| 模块导入声明 | — | — | 476 预览 | 494 二轮 | **511 正式** | — |
| 原始类型模式 | — | — | 455 预览 | 488 二轮 | 507 三轮 | 532 五轮 |

**三条从这张表读出来的结论**（面试可直接用）：
1. **String Templates 停在第二轮预览**：21 预览 → 22 二轮 → **23 起彻底消失**。所以「String Templates 已经正式」是错的，说「被搁置了」才准确
2. **虚拟线程的坑是 24 修的**：JEP 491 *Synchronize Virtual Threads without Pinning*。所以「虚拟线程在 synchronized 里会钉住」在 **JDK 24 之前**成立，之后不成立——按版本说才专业
3. **ZGC 的路线是「先可选、再默认分代、最后删掉非分代」**：21 引入分代（可选）→ 23 分代变默认 → 24 移除非分代模式。到 27 再谈 GC，只有 G1（默认，全环境）与分代 ZGC/Shenandoah 三条路

## 六、会被怎么问（按你的简历逐条准备）

**Q：你项目原来是 Boot 2.3.4 + Java 8，现在让你升级，你会怎么干？**

答题骨架（都是可核事实）：
1. **JDK 先升**：Java 8 → 21。注意 21 里 `451` 已经「准备禁止动态加载 Agent」，很多字节码增强框架（老版本）会打警告；32 位 x86 在 25 被彻底移除（503）
2. **javax → jakarta**：Boot 3.0 起换命名空间，对应 Servlet 6.1 / Tomcat 11。**这一步是硬迁移**，所有 `javax.servlet.*`、`javax.persistence.*` 都要改，第三方 starter 必须有支持 jakarta 的版本
3. **Spring Framework 7**：Boot 4.1 要求 7.0.10+，配置属性和废弃 API 会有一轮清理
4. **构建/容器**：Gradle 8.14+ 或 9.x、Maven 3.6.3+
5. **验证顺序**：先跑通单测，再压测，最后看 GC 日志（G1 默认，堆 >32G 或延迟敏感再考虑 generation ZGC）

**Q：虚拟线程你用了吗？**

正确说法：
- 21 起**正式**（JEP 444），不是预览
- 它是 **JVM 调度**（M:N），不是 OS 线程，`Thread.ofVirtual()` / `Executors.newVirtualThreadPerTaskExecutor()`
- **不适合 CPU 密集**，只对「阻塞等待多」的场景有收益（IO、RPC、DB）
- 坑：**JDK 24 之前，`synchronized` 块里阻塞会 pin 住载体线程**；**JDK 24 的 JEP 491（Synchronize Virtual Threads without Pinning）修掉了**。所以这题要先问「你说哪个版本」
- 配套的 Structured Concurrency（453）到 27 仍是第七轮预览 → **生产别用**

**Q：GC 怎么选？**

| 你说什么 | 对不对 |
|---|---|
| 「JDK 9 起 G1 是默认」 | ✅（27 的 JEP 523 进一步把 G1 默认推到所有环境） |
| 「ZGC 是默认」 | ❌ 常见错误。ZGC 21 起有分代版（JEP 439），但**不是默认** |
| 「CMS」 | ❌ 早被移除，现在提它说明很久没碰 JVM |
| 「堆大又要求低延迟 → Generational ZGC；一般服务 → G1；吞吐优先 → Parallel」 | ✅ 这是能落地的答法 |

**Q：语言层面有什么变化？**

按这个顺序答（都正式化了）：`var`（10）→ `record`（16）+ **record patterns / switch 模式匹配（21）** → 文本块（15）→ sealed class（17）→ **Scoped Values（25）**。

⚠️ `String Templates` 的最终归宿已核清：**21 预览（430）→ 22 第二轮预览（459）→ 23 起从 JEP 列表消失**。所以别说「已经正式」，准确说法是**停在第二轮预览、被搁置**。
